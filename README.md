# Codex Proxy Manager

让兼容应用使用独立代理入口，而不启用 Windows 系统代理。

一个由 **Rinko** 维护的 Windows 桌面代理管理器，内置 Codex 启动入口。可以导入自己的订阅或节点，也可以连接现有代理软件，集中查看连接状态、实时流量、节点延迟，并手动启动、停止和切换节点。

> 当前版本：**v0.10.2 预发布**。已通过本地回归及云端构建和测试；独立 Windows 环境验收尚未完成，不是 v1.0 正式版。它不是 OpenAI 官方产品，不提供节点、订阅或账号，也不保证目标服务一定可用。

## 它解决什么问题？

如果你希望 Codex 使用代理，但不想让浏览器、商店、游戏等其他独立启动的软件也被切换到系统代理，本项目提供一个应用级启动入口。你可以在面板里控制代理会话，不必每次手动拼接启动参数。

它用启动参数和子进程环境变量告诉兼容应用连接哪个代理入口，再由本地 Mihomo 核心按规则选择直连或节点。**是否需要代理由配置规则判断，不是 Codex 自行智能判断。**

正常启停不修改 Windows 系统代理或全局环境变量。这不是系统级透明拦截：不识别代理参数或环境变量的程序，不会仅因被添加到管理器而自动获得代理。

## 主要功能

- 查看会话状态、当前节点、上传/下载速度、累计流量与连接数。
- 导入订阅、分享链接，保存多个代理档案。
- 节点延迟测试、手动切换、选择最低延迟节点。
- 节点名称/协议搜索、排序、收藏及仅看收藏。
- 可选启动后自动选优、连续失败后自动切换、远程订阅刷新。
- 添加兼容应用，为应用绑定独立档案；当前一次只运行一个应用会话。
- 只读连接诊断，以及用户主动导出的脱敏报告。

**“速度”是当前流量速率，不是线路最大带宽；“测试节点延迟”不是下载测速。** 空闲时显示 0 B/s 可以是正常情况，最低延迟也不保证下载最快或应用登录成功。

## 选择适合你的接入方式

| 你已有的资源 | 选择的来源 | 其他代理软件是否要运行 | 节点在哪里切换 |
| --- | --- | --- | --- |
| 订阅 URL | 订阅 URL | 不需要 | 本管理器 |
| 一个或多个节点分享链接 | 分享链接 / Base64 | 不需要 | 本管理器 |
| 代理软件的本地 HTTP/SOCKS5 端口 | 本地 HTTP / SOCKS5 | 需要 | 通常在上游软件中 |
| 代理软件的本机 Mihomo 控制接口 | 外部 Clash / Mihomo API | 需要 | 本管理器可控制其策略组 |

分享链接可交由 Mihomo 处理 VLESS、VMess、Shadowsocks、Trojan、Hysteria2、TUIC 等协议；实际支持取决于核心版本、链接字段和服务端配置。不保证兼容所有订阅和客户端版本。

Clash、Mihomo Party、v2rayN、NekoBox 等软件能否接入，以它们是否开放合适的本地代理端口或兼容控制接口为准，不是按软件品牌自动适配。

即使选择外部客户端，**当前版本仍需要本项目目录中的 Mihomo 和规则库**。本管理器切换外部客户端的共享策略组时，其他使用该策略组的软件也可能随之更换节点。

## 如何开始？

1. 获取源码，在仓库根目录运行下方构建命令生成 EXE；若获得维护者提供的管理器预发布包，则先完整解压。源码 ZIP 本身不含 EXE。
2. 单独准备 Mihomo Windows x64 核心和规则库，按 [快速入门](QUICKSTART.md) 的目录结构放好。本仓库与管理器预发布包不附带这些第三方文件。
3. 打开管理器，完成文件检查，再添加自己的代理来源；请勿把真实订阅填写到仓库文件中。
4. 完全退出目标应用，在面板点击“启动应用”。已有进程无法补上这次启动的代理参数。
5. 查看节点与连接状态，并在目标应用中实际发送一次请求。异常时使用“连接诊断”。

构建命令（PowerShell）：

```powershell
& '.\manager\build.ps1'
```

目标环境为 Windows x64 和 .NET Framework 4.x；本地验证不代表所有 Windows 10/11 版本均兼容。macOS、Linux、Windows ARM64、任意游戏/UWP 透明代理不在当前验证范围。

## 日常操作与限制

- 打开管理器不会自动启动 Codex、其他应用或代理核心；只有手动点击面板“启动应用”或托盘中的启动项才会启动。v0.10.2 已移除自动启动选项，旧配置中的该设置也不再生效。
- 点击“切换到选中节点”进行切换；现有连接会被断开并重新建立，正在进行的请求可能受影响。
- “停止专用代理”会关闭本项目核心，不会去关闭外部上游客户端。
- 关闭面板会进入托盘；“退出管理器”才会结束管理器。
- 目标应用退出后，管理器会在检测到退出时自动停止核心。
- 停止代理后，仍运行的目标应用保留旧代理参数；完全退出后再按需要重新启动。
- 自动化、搜索、收藏及异常恢复的具体行为见 [详细手册](USER_GUIDE.md)。

如果其他客户端已启用系统代理、TUN 或 VPN，本项目不会替你关闭它们，也不能保证其他软件的原网络路径未被它们改变。辅助子进程可能继承代理环境变量；这不是严格的进程防火墙。

## 隐私与安全

真实设置、订阅、节点、日志和缓存保存在 Windows 当前用户的本地应用数据目录下（具体位置见 [隐私说明](PRIVACY.md)），不应进入源码仓库或反馈附件。**这些文件不是加密保险箱；订阅、节点名和原始日志都应视为敏感信息。**

管理器不自动上传诊断报告。但连接节点、订阅更新、健康检查和手动测速会产生相应网络请求，不代表没有外部通信。发布前有自动凭据模式检查，仍需人工复核。
