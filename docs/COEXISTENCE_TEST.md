# Microsoft Store / 游戏共存验收

这是可选的后续排障步骤，不是已通过的验收记录。维护者决定 v0.11.3 发布时暂不执行，不作为此次预览发布前置条件。代码和本机模拟回归无法认证商店/游戏体验；商店/游戏启动后变慢的问题仍未定位。

## 安全边界

由用户在方便时主动操作，不自动退出 Codex、终止游戏、清空缓存、改系统代理/TUN、替换节点或修改 WindowsApps 权限。不登录新账号、不购买或执行游戏内操作。先保存未完成工作；若当前 Codex 不是带匹配代理参数启动，首次测试需由用户安排重新打开，不能强行接管。

记录管理器版本、Windows 构建号和可公开的观察结果。不要记录节点名/IP、订阅、账号、密钥、游戏登录信息或原始日志；反馈可使用检查过的脱敏报告。

## 对照方法

保持网络、上游客户端、页面/游戏、节点及其他后台工作一致。不要为了这次测试临时切换其他客户端的全局代理；若它的 TUN/系统代理正在运行，仅记为“存在外部网络影响”，本轮结果不能单独归因于管理器。

商店先选固定页面作为测试目标。每个状态测三次，首次冷启动/缓存差异单独注明；每次测试前等待核心启动和后台初始化稳定。游戏只测同一启动/联网步骤，报错只记类别，不粘贴账号或含凭据的错误内容。

| 状态 | 用户操作 | 观察内容 |
| --- | --- | --- |
| A：管理器关闭 | 保持其他网络条件不变 | 商店固定页三次耗时、游戏联网是否正常 |
| B：仅打开管理面板 | 不点击启动，不启动核心/目标应用 | 重复相同步骤，判断面板本身是否影响体验 |
| C：启动专用代理会话 | 用户主动点击“启动 / 恢复”，不测速、不切节点 | 重复相同步骤，记核心初始化与稳定后的区别 |
| D：停止专用代理 | 用户点击停止，其他应用保持不变 | 复查是否恢复；目标应用保留代理参数、暂时断网可能是正常结果 |
| A2：退出管理器后复查 | 从托盘退出，再重复基线 | 判断差异是否可重复，而非缓存/偶发网络抖动 |

## 判断与下一步

- 仅 B 变慢：先调查界面刷新/后台任务；B 按当前设计不应启动核心或目标应用。
- 仅 C 可重复变慢，D/A2 恢复：继续核对本机 CPU/磁盘、核心进程/DNS/规则库初始化以及其他代理客户端的共同影响；这是定位线索，不是根因证明。
- A/A2 也不稳定：先改善对照条件，不立即修改系统网络或宣称核心有问题。
- 遇到明显网络错误：结束本轮，保存脱敏结果。不要自动放宽防护或更改全局代理作为“修复”。

尚未执行时保持“待验证”；真实共存及高 DPI/干净 Windows 检查全部完成之前，不据此标为 v1.0。
