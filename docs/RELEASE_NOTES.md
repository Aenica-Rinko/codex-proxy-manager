# v0.11.0 界面与隐私预览版

作者：Rinko · GPL-3.0-only · Windows x64 · [发布页](https://github.com/Aenica-Rinko/codex-proxy-manager/releases/tag/v0.11.0)。

- 主窗口改为固定导航、顶部会话操作和完整节点工作区，取消混杂的滚动按钮区与固定 LIVE 标记。原有代理、节点及档案功能保留。
- 新增独立“隐私保护”入口：明确区分配置、参数请求和行为验证，不把开关状态当作实测结果。
- 新日志只保存固定事件及错误类别；按约 1 MB / 一份备份 / 7 天期限轮转。停止会话后可确认清理指定日志，历史日志不会被追溯脱敏。
- 新增截图隐私模式，隐藏主界面节点/应用/档案信息及工具提示；不改变节点身份与路由，可能显示私人信息的管理入口会受限。
- Chrome / Edge 可主动运行隔离本地 WebRTC 测试，使用临时独立浏览器和回环服务。有效基线、UDP/host 观察及代理 HTTP 请求共同决定结果；不认证当前会话或公网无泄漏。Codex/Electron 仍为未验证。

## 下载与首次使用

选择 `CodexProxyManager-v0.11.0-manager-only-preview.zip`，同名 `.zip.sha256` 用于校验。完整解压后运行根目录 `CodexProxyManager.exe`，不要只取出 EXE。包内包含使用文档、恢复工具、完整 GPL 许可证、对应源码和构建脚本；不含 Mihomo 核心、规则库、节点、订阅或私人配置。

首次使用按 [快速入门](QUICKSTART.md) 准备核心与规则库，再导入自己的代理来源。打开面板不会启动目标应用；完全退出目标应用后，主动点击顶部“启动应用”。左侧“隐私保护”查看配置/验证状态，右下角“截图隐私模式”隐藏本项目界面信息。

## 从旧版升级

保存当前工作，停止会话并从托盘退出旧管理器。将新版完整解压到新目录，按快速入门准备核心和规则，并将快捷方式指向新版 `CodexProxyManager.exe`。原 `%LOCALAPPDATA%\CodexProxyManager` 用户目录保留，无需重新导入节点或删除设置。

WebRTC 限制默认请求开启，DNS 和 QUIC 限制默认关闭；修改这些选项后需完全退出目标应用并从管理器重新启动。旧日志不会被追溯脱敏；要清理时，停止会话，在隐私中心主动确认清理指定日志。旧版 v0.10.3/v0.10.2 附件不覆盖，保留供需要时回退。

## 已知问题与验证边界

**启动应用后 Microsoft Store 或游戏联网可能变慢的问题仍未定位和修复。** 本次界面与隐私改动不宣称解决该问题或提升代理速度。

本地回归、打包和 Chrome 隔离回环测试通过；该测试不认证当前会话、公网 DNS、IPv6 或所有网络路径无泄漏，Codex/Electron 的 WebRTC 行为仍未验证。凭据加密与系统级防直连未实现。独立干净 Windows、高 DPI、多浏览器版本和桌面点击验收尚未全部完成，继续以预览版发布；没有安装器、自动更新或代码签名。

反馈请到 [GitHub Issues](https://github.com/Aenica-Rinko/codex-proxy-manager/issues)，提供版本、复现步骤及检查过的脱敏报告。不要上传节点、订阅、密钥、原始日志或私人备份。

# v0.10.4 隐私启动选项（历史本地开发版本，未公开发布）

v0.10.4 当时只用于本地测试，改动已纳入 v0.11.0。当时公开下载为下面的 v0.10.3。Microsoft Store/游戏变慢问题仍未修复。

# v0.10.2 历史预发布说明

作者：Rinko。许可证：GPL-3.0-only。这是面向早期测试用户的管理器预览版，不是 v1.0 稳定版。[发布页面与下载附件](https://github.com/Aenica-Rinko/codex-proxy-manager/releases/tag/v0.10.2)。

## 已知问题：其他应用联网可能变慢

已收到在手动启动应用后 Microsoft Store 加载及游戏联网明显变慢的反馈。原因尚未定位，**本版本未修复**；不承诺对其他应用性能零影响。只打开管理面板与启动代理会话是不同阶段，反馈时请说明问题发生在哪个阶段。

如遇到问题，请先保存工作，停止专用代理并完全退出通过管理器启动的目标应用，再对照测试。对商店或游戏共存性能敏感的用户建议暂缓使用，等待后续修复。请到 [GitHub Issues](https://github.com/Aenica-Rinko/codex-proxy-manager/issues) 提交不含私人节点、订阅、密钥或原始日志的复现步骤。

## 本次变化

- 打开管理器不再自动启动 Codex、其他应用或代理核心。
- 删除“启动管理器后自动打开当前应用”选项，旧配置中的 `AutoStart` 设置也不再生效。
- 只有主动点击主面板“启动应用”或托盘启动项，才会启动当前选择的应用。
- 保留应用/档案绑定、节点收藏、自动选优和故障切换；后两项只在手动启动的会话中工作。

## 第一次使用

1. 完整解压 ZIP，不要在压缩包内直接打开 EXE。
2. 按该版本随附的快速入门准备核心与规则文件，打开 `CodexProxyManager.v0.10.2.exe`（历史版本文件名）。
3. 完成文件检查，导入自己的代理来源。保存后应停留在面板，不启动应用。
4. 完全退出目标应用，再手动点击“启动应用”；用实际请求确认连接。
5. 点击“停止专用代理”结束会话。若目标应用仍运行，它仍保留启动时的代理参数，需要完全退出后再重新打开。

连接异常时先使用“连接诊断”。反馈前检查截图和报告，不要提供节点链接、订阅地址、控制密钥、原始日志或个人路径。

## 从旧版升级

- 先保存目标应用中未完成的工作，再停止会话并从托盘退出旧管理器。关闭面板只是最小化，不是退出。
- 解压新版到普通、可写且不公开同步的目录，按快速入门准备运行文件；不要用示例文件覆盖真实档案。
- 用户配置继续由当前 Windows 用户的数据目录管理。升级不要求删除用户数据；如自行备份，请保存在私人位置，不要上传备份。
- 将自己的快捷方式指向新版 EXE。启动新版后检查版本、所选应用、档案和节点列表，再手动启动应用。
- 曾经勾选的自动启动不再生效。这是本次有意改变的行为，不是配置丢失。

## 已知限制与验收边界

目标环境为 Windows x64 / .NET Framework 4.x。当前一次只支持一个应用会话；不支持给任意游戏或 UWP 程序做透明代理。实时流量不是最大带宽，低延迟不保证应用登录成功。

本地测试使用隔离目录、测试子进程和本机测试上游。它们不能代替独立 Windows 用户、四类真实代理来源、目标服务登录和第三方软件共存验收。逐项记录见 [验收记录](ACCEPTANCE.md) 与 [发布检查清单](RELEASE_CHECKLIST.md)。未完成这些检查前，不标记为 v1.0 或承诺全面兼容。
