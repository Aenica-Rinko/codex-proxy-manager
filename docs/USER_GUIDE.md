# 详细使用手册

首次安装请先完成 [快速入门](QUICKSTART.md)。产品概览见 [README](../README.md)，隐私说明见 [PRIVACY](PRIVACY.md)。

本地源码构建请从 `app/` 启动；发布 ZIP 请从解压根目录启动。下文 EXE 命令均以应用目录为工作目录。目录结构和旧版本迁移见 [FILE_LAYOUT.md](FILE_LAYOUT.md)。

## 数据位置

程序目录只保存源码、模板和不可变运行文件。真实节点、凭据、日志和状态位于：

```text
%LOCALAPPDATA%\CodexProxyManager
├── settings.json
├── node-preferences.json # 按档案保存的收藏，仅第一次收藏时创建
├── profiles\
├── core-data\
├── logs\
└── manager-state.json   # 仅代理运行期间存在
```

不要把用户数据目录提交到 GitHub。旧版根目录私人配置已经迁移并删除，新版本只读取 `%LOCALAPPDATA%` 中的活动档案。

## 应用管理

### v1.2.0 第三批：主题、快捷键与会话记录

左侧“切换浅色主题／切换深色主题”或 **Ctrl+T** 切换主面板主题。偏好保存在用户目录 `ui-theme.txt`；原有配置、诊断、隐私等弹窗仍沿用深色样式，会话记录窗口跟随主题。没有跟随系统或全局主题承诺。偏好损坏时不覆盖原文件，当前主题仍可切换，保存失败写入会话记录。

- Ctrl+1：连接概览；Ctrl+2：节点与策略；Ctrl+F：节点页搜索。
- Ctrl+H：会话记录；F1：已有帮助与版本；Tab／Shift+Tab 在可用控件间移动。
- 不提供一键启动／停止快捷键，避免误操作。截图模式下搜索、会话记录及帮助入口遵守原隐私限制。

首页“会话记录”显示打开时的操作快照，最近 100 条、倒序、仅内存保存。记录启动、恢复、停止、节点／档案切换、订阅刷新和失败等固定结果，不接受原始错误内容、节点名、地址或凭据。可以手动清空，退出管理器后清空；既有脱敏日志保留策略不变。记录不是流量审计，也不证明联网或隐私保护有效。

修复切页时固定高度丢失缩放比例，以及节点列表列宽未按实际列宽计算的问题。已做布局比例模拟检查，但尚未完成真实混合 DPI 多屏、屏幕阅读器和所有弹窗的缩放验收。

### v1.2.0 第二批：页面入口

- **连接概览**：当前应用、启动条件、本地入口状态、流量、当前代理档案；“查看节点与策略”进入节点页。
- **节点与策略**：搜索、排序、收藏、测速、订阅刷新、节点切换；右上方“策略组与引用”打开原有组管理窗口。停止时提示先启动，历史列表仅供参考。
- 启停按钮始终留在顶部，切换页面不会改变会话、选择或筛选。运行时停止按钮强调显示；忙碌时禁止重复操作。
- 截图模式同时隐藏档案摘要和节点名，组详情仍禁止打开。更换应用／档案仍须先停止代理。

### v1.2.0：先看启动状态

打开管理器只检查状态，不启动应用或代理。检查在后台执行，应用运行状态约五秒刷新；切换应用／档案后重新检查。Codex 安装目录的提示性查询缓存最长一分钟，避免频繁启动查询进程；安装／修复后提示可能稍晚更新。实际启动仍重新查找安装目录。

| 按钮 | 含义与操作 |
| --- | --- |
| 正在检查… | 等待后台检查；不能重复启动。 |
| 启动应用并连接 | 应用未运行，用户点击后才开启代理并启动应用。 |
| 恢复代理 | 运行中的兼容 Chromium/Electron 主进程参数匹配，点击恢复入口，不重启应用。 |
| 查看启动说明 | 应用运行中但无法确认参数匹配；保存工作、完全退出应用，再从管理器启动。 |
| 查看准备说明／查看检查说明 | 检查组件、档案或应用安装路径，处理后等待重新检查。 |
| 代理运行中 | 会话已启动；使用旁边的停止按钮。停止不关闭应用，也不保证自动直连。 |

这是启动前提示，不是网络或隐私认证；点击启动时仍重新检查。主面板“本地代理入口”只反映本机入口／控制接口状态，不能据此判断目标网站可用。目标网站连通性默认未检测，不会为了刷新状态自动访问网站。环境变量模式不支持运行中免重启恢复。

以下旧版“启动 / 恢复”的描述在 v1.2.0 中对应上表的具体动作。

1. 停止当前专用代理，点击左侧导航的“管理应用”。
2. 点击“添加应用”，填写名称并浏览选择已安装程序的 EXE。
3. 选择启动方式：支持 Chromium/Electron 代理参数的程序选择第一项；自行识别 `HTTP_PROXY` 等变量的程序选择第二项。
4. 选择该应用的代理档案，点击“保存并设为当前”。
5. 首次使用先保存工作、完全退出普通启动的已有进程，再点击“启动 / 恢复”。窗口标题显示当前应用名称；匹配启动参数的运行中 Chromium/Electron 应用可直接恢复。

每次运行一个应用会话。保存的当前应用会在下次打开管理器时继续被选中，但不会自动打开；只有手动点击面板“启动应用”或托盘启动项才会启动。回到“管理应用”选中 Codex 并保存，即可恢复 Codex 入口。

### 应用隐私选项（v0.10.4 起）

在“管理应用”下半部分可以设置：

- **请求限制 WebRTC 非代理 UDP**：默认开启。兼容浏览器限制 WebRTC 的非代理 UDP；可能影响语音/视频。
- **限制浏览器本机 DNS 解析**：默认关闭。需要更严格限制时勾选；可能使内网域名或需要直连解析的功能不可用。
- **关闭 QUIC / HTTP3**：默认关闭。兼容浏览器改用可回退的 TCP 请求，可能改变速度。

点击“保存并设为当前”，完全退出应用已有进程，再手动点击“启动应用”。关闭选项后也需要完全退出再启动；正在运行的进程无法补加或撤销参数。这些偏好按应用单独保存，环境变量模式不支持它们。

“连接诊断”中的 `PRIVACY` 项显示请求的限制和验证边界，不能用它判断是否实际存在泄漏。尤其 Codex 等 Electron 应用可能忽略 WebRTC 参数；本版本没有宣称已证明 Codex 不泄漏。说明与测试范围见 [隐私说明](PRIVACY.md)。

这不是任意程序的透明流量接管。不支持上述代理方式的游戏、UWP 应用或其他程序，不能仅靠添加 EXE 获得代理。环境变量可能被子进程继承，但分流规则仅覆盖所选程序名；使用不同程序名的辅助进程不会自动增加规则。

新增应用使用临时 `session-config.yaml` 替换标准规则中的程序名，保留原始档案的节点和策略；正常停止后清理临时副本。该文件仅位于用户数据目录，可能含节点凭据。Codex 继续直接读取原档案。没有标准进程规则的自定义 YAML 会明确报错。

升级时旧设置自动补入 Codex 默认应用，原有节点和档案保留。删除被绑定的代理档案后，应用改为跟随当前档案。通过“管理代理档案”设置新当前档案时，当前应用也改为跟随它。设置保存使用临时文件加原子替换，减少写入中断损坏配置的可能。

## 首次配置

没有用户设置时，先显示“开始使用”引导；缺少核心或规则文件时也会显示该窗口。检查只读取必需文件是否存在且非空，缺失时不能继续，不会自动下载或改变系统设置。组件补齐后点击“重新检查”，再继续到档案管理器。打开管理器和保存设置都不启动应用。v0.10.2 移除了自动启动选项，旧的 `AutoStart` 字段读取时被忽略，下次保存设置时会移除；其他偏好保持不变。

档案管理器可以选择：

1. 订阅 URL：支持 Mihomo/Clash YAML、逐行 URI 和 Base64 内容；
2. 分享链接：每行一个 URI，也可以直接粘贴完整 Base64；
3. 本地代理：连接其他软件开放的 HTTP/SOCKS5 端口。
4. 外部 Clash/Mihomo API：Codex 流量连接外部客户端的本地 HTTP/mixed 端口，同时由其 REST API 提供节点列表、测速、切换和订阅刷新。
5. 本地文件导入：选择 YAML/YML/TXT，从含内联 `proxies` 的 Clash/Mihomo YAML、分享链接或 Base64 文本复制节点。

本地文件导入最大 10 MiB，支持 UTF-8 或带 BOM 的 UTF-16，拒绝链接路径、备用数据流、空文件及不支持的编码/类型。选择文件不立即导入；点击“添加并设为当前”后在后台校验，期间不能重复添加或关闭档案窗口。成功显示实际解析的节点数，失败保留编辑内容供重试。

本地内容复制到私人用户目录，不保存来源路径或上传文件。原文件不修改，不自动同步；重新导入会创建新档案。v1.1.0 保留内联节点、策略组和引用，不继承原 TUN、DNS、端口、全局规则。依赖远程／外部文件 provider 的组需先展开；其他客户端 JSON 暂不支持。导入不启动目标应用、不开系统代理、不主动测速。保存失败会回滚本次新建文件，锁定文件仍可能保留。只导入可信来源；兼容范围和操作见 [策略组与故障切换](STRATEGY_GROUPS.md)。

不论使用哪种来源，管理器都会生成带 Codex 进程规则的配置。旧档案仍可使用；需要保留原策略组时，请重新导入原文件。子进程是否走节点由档案规则决定。URL 订阅仍采用节点 provider，不保留整份订阅的策略组；默认每小时更新，provider 健康检查间隔为 5 分钟。

外部 API 模式目前只接受 `localhost`、`127.0.0.1` 或 `::1` 控制地址，避免控制密钥经网络明文泄露。管理器切换的是外部客户端中的策略组；如果其他软件也使用同一个外部客户端和策略组，它们也会看到节点变化，但本项目不会把这些软件的流量导入 Codex 专用入口。

v0.10.1 中的“测试外部控制接口”在后台检查，单个请求的连接/读取超时为 2.5 秒。检查期间可继续操作或关闭窗口，不能重复发起同一个检查；结果对应点击时的地址和密钥。检查不跟随重定向、不继承系统 HTTP 代理，也不保存档案或切换节点。接口成功仅表示结构和鉴权有效，不代表外网可用。

## 自动化策略

v0.11.2 的主面板刷新在后台执行，单次轮询不重叠；停止或切换后不会回填旧结果。显示“入口可用”只表示本地入口/控制统计可用，不证明节点或目标服务可登录。控制请求有明确截止时间；本次优化不等于修复商店/游戏联网变慢。

在“管理代理档案”中可以启用：

- `启动后测速并选择最快节点`：入口已选策略组时保留该选择；直接选中节点时，测速后选择有效延迟最低的成员。
- `节点连续失败时自动切换`：约每 30 秒检查当前引用链上的节点，连续 3 次失败才在最后一级 select 组内尝试其他可用代理；切换尝试后冷却 120 秒，不自动改选直连。

fallback、url-test、load-balance 由 Mihomo 按导入参数运行，管理器不会覆盖其自动选择；上述勾选只控制管理器对 select 组的补充切换。全部不可用时不改选 DIRECT。管理器切换后尝试清理本项目核心旧连接，失败时新连接仍使用已保存的选择。核心自动组切换不保证已有长连接立刻迁移。

运行中需要新增或切换档案时，先点击“停止专用代理”，再点击“管理代理档案”。也可以退出管理器后执行：

```powershell
& '.\CodexProxyManager.exe' --setup
```

## 新界面与隐私中心（v0.11.0）

左侧固定导航提供“连接概览”“隐私保护”“管理应用”“代理档案”“连接诊断”；帮助和退出位于导航底部。顶部固定显示“启动 / 恢复”和“停止代理”（v0.11.0 中启动项名为“启动应用”）。节点搜索、排序、收藏、延迟测试、选优、刷新及切换集中在节点列表区域，不需要滚动寻找按钮。

主界面右下角“截图隐私模式”一键隐藏私人显示信息。节点用编号代替，切换和收藏仍操作原来的节点；退出截图模式后恢复名称。模式开启时，应用/档案管理及可能展示路径的帮助入口暂时禁用，搜索框清空并禁用，通知和错误详情也隐藏。该功能只覆盖本项目界面，不隐藏其他窗口或加密磁盘配置。

“隐私保护”独立窗口可以在会话运行时查看状态。要修改网络选项，停止会话后点击“编辑应用隐私选项”，保存并完全退出目标应用，再手动启动。Codex/Electron 显示“行为未验证”是当前验证范围，不是程序报错。

Chrome / Edge 用户可主动点击“运行本地 WebRTC 测试”。测试在独立临时浏览器中进行，只使用回环 HTTP/STUN 服务；不会读已有浏览器档案。通过结果仅代表隔离本地测试，不认证当前会话或公网无泄漏。其他应用的测试按钮禁用。关闭隐私窗口会取消测试。

新日志只记录固定事件和错误类别，并按大小/7 天保留期轮转。旧日志未自动脱敏；需要移除时先停止会话，在隐私中心点击“清理本项目日志”并确认。只删除三份指定日志和各自 `.1` 备份，不删除节点、设置或其他文件，删除后程序内无法恢复。截图模式下日志目录入口禁用。

## 日常使用

1. 首次或普通方式启动的应用需先保存工作并退出；已带匹配参数启动的兼容应用不需要退出；
2. 打开管理器；
3. 手动点击“启动 / 恢复”（或托盘对应项），管理器核对运行状态后启动核心；未运行时通过专用参数及环境变量启动应用，匹配时仅恢复代理；打开管理器本身不会执行此步骤；
4. 所选应用退出约 4 秒后，管理器停止核心并清理会话状态。

关闭管理面板只会最小化到托盘。“退出管理器”或“停止专用代理”会停止本项目的核心，但不关闭目标应用、不自动改为直连。

### 应用运行时恢复代理（v0.11.3，包含 v0.11.1 的恢复功能）

**操作顺序：首次从管理器启动应用 → 应用保持运行 → 停止代理 → 启动 / 恢复。不能先正常打开应用再让管理器中途接管。恢复要求代理入口和当前隐私参数匹配，仅适用于兼容 Chromium/Electron 模式。**

如果 Chromium/Electron 应用之前带本管理器的代理参数启动，停止代理后可保持应用运行，再次点击“启动 / 恢复”；重新打开管理器也会在点击时核对，不需要反复退出应用。检查匹配的可执行文件、主进程、代理端口、回环绕过项和全部当前隐私参数；只读本机，不保存原始命令行。代理重新监听后应用可能需要自行重连。

这不是修改任意正在运行应用的代理设置。普通方式打开的应用没有所需参数；环境变量模式无法通过命令行核实；端口或隐私设置改变、参数冲突、检查失败也不能恢复，会提示原因且不关闭应用。修改隐私选项后仍需保存工作并退出目标应用，再从管理器重新启动。若要停止后改用直连，也需退出并正常启动。参数匹配仅证明启动请求一致，不证明 Electron 或应用内部所有请求都遵循代理。

使用自建节点或订阅档案时，不需要开启其他代理软件。使用本地上游/外部 API 档案时，上游客户端仍需运行；该客户端自己的系统代理或 TUN 设置不受本项目管理。

## 节点搜索、排序与收藏（v0.9）

节点列表上方可以输入名称或协议关键字，搜索不区分大小写。排序菜单提供原始顺序、名称 A–Z 和延迟从低到高；没有有效延迟的节点排在最后。排序只使用已有测量结果，不会自动测速。

选中一个节点，点击“收藏选中节点”；已收藏节点显示 `★`，再次选中可取消收藏。“仅看收藏”可与搜索同时使用。收藏按代理档案 ID 和完整节点名称匹配，重启后保留；同名但不同档案的节点不会互相影响。订阅暂时移除节点时保留收藏，节点同名返回后重新显示；节点改名则需要重新收藏。

底部始终显示“显示数量 / 总数量”。当前使用的节点被筛掉时会提示，但不会切换连接；点击“清除筛选”可恢复全部节点和原始顺序。刷新列表保留当前筛选；切换档案会清空搜索、关闭仅看收藏并加载新档案收藏。筛选隐藏的选中项不会继续成为手动切换目标。

搜索、排序和收藏均不更改路由、节点配置或自动选优范围。“测试节点延迟”和“选择最低延迟”仍处理完整节点列表，而不是仅处理可见项。收藏不代表优先使用，也不是额外的健康保证。

收藏位于用户数据目录的 `node-preferences.json`，使用临时文件加原子替换保存，不写入 `settings.json` 或代理 YAML。该文件含私人节点名称，不应提交到 GitHub或当作脱敏报告分享。损坏或不可写时显示失败提示并保留原文件，不会影响代理会话。

## 连接诊断与报告（v0.8 起）

在左侧导航点击“连接诊断”，代理运行或停止时均可检查。默认只检查本机文件、进程、端口和本机控制接口，不发送外网探测请求，也不会启动应用、切换节点或修改系统代理。

- 文件和端口检查帮助发现文件缺失、入口无法连接或停止后的端口占用；
- 控制接口检查区分鉴权失败、超时和响应异常；
- `FLOW` 只统计目标程序的活动连接，区分代理、直连、拒绝和路径未知，不展示目的地址；
- 系统代理检查只读取手动代理和 PAC 设置，不检测 TUN、VPN 或自动发现代理，也不会替你关闭其他软件的代理；
- 需要外网探测时，勾选“测试当前节点的外网延迟”，再点“重新检查”。核心会通过当前选择请求 `https://www.gstatic.com/generate_204`。

没有观察到连接不等于代理失败：应用可能空闲、连接已结束，或核心缺少进程信息。请在应用中发起请求后重查。端口可连接、接口正常或节点探测成功，也不等于应用服务可以登录。

点击“导出脱敏报告”选择本地 TXT 文件。导出内容与当前显示一致，仅包含检查时间、固定诊断信息及连接计数等结果，不附加原始配置、日志、节点名称和地址、订阅、密钥、用户名、文件路径或访问记录。程序不会自动上传；分享前仍建议自行查看内容。

也可以单独打开诊断窗口，无需启动代理或关闭正在运行的管理器：

```powershell
& '.\CodexProxyManager.exe' --diagnostics
```

单独诊断读取已保存的当前应用与档案；无活动核心时跳过控制接口和外网探测。它不会启动正常管理器会话或保存设置。

## 异常恢复

运行期间会启动独立 watchdog。新状态记录会话标识、核心路径和进程启动时间；异常退出时仅停止身份吻合的核心，不按 PID 或名称盲目终止，无法核实的旧核心不会由 watchdog 强制停止。新状态包含 `NetworkMode: process`，停止、恢复脚本和 watchdog 均跳过 Windows 代理写入；旧版状态仍支持恢复，且只在系统代理仍指向本项目时恢复。旧 watchdog 发现状态已属于下一次会话时直接退出。状态是私人本机文件，不要上传。

如果网络仍有异常，在应用目录运行 `tools/Restore Codex Network.cmd`。恢复脚本兼容应用目录中的旧状态和 `%LOCALAPPDATA%` 状态；它不是日常启动入口，也不会在升级时自动执行。
