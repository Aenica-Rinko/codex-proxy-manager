# 全项目审查记录 · v1.1.0

日期：2026-10-16。作者：Rinko。本记录描述 v1.1.0 的本地审查范围；公开版本、附件与对应提交的 CI 结果以 GitHub 为准，不把发布等同于全面兼容认证。

## 本轮范围与结论

枚举源码、测试、PowerShell 构建／发布／迁移脚本、CI 工作流、全部文档／模板／许可证和第三方依赖；检查本地 app、runtime 和 artifacts 的边界。第三方内核／数据库仅检查存在性及隔离运行行为，不宣称审计其二进制内部或来源；.git 内部凭据和完整历史不纳入安全认证。私人节点只在本机读取校验，不写入报告、源码或发布包。

代码规模仍适合轻量 Windows 工具。核心会话、节点控制、导入解析已有独立模块；主要维护风险是主窗口编排仍偏大、系统兼容与原生 UI 的自动验证不够完整。

## 本轮修复

- 本地导入只保存节点、丢失组结构：使用有界 YAML 结构解析保留节点／组／引用；安全闭合图校验，拒绝缺失、重复与循环引用；节点与组分别计数。
- 故障切换可能覆盖组策略：沿选择链定位最后一级 select；连续三次失败、120 秒冷却、过期结果复核、排除直连候选；自动组由核心处理。
- 手动切换缺少成员校验：仅允许现有选择组成员；清理旧连接失败不再伪装成选择失败。
- 分享链接等来源保存设置失败会留下孤立文件：新文件创建采用事务跟踪，失败时只清理本次创建的文件。
- 应用列表保存失败与内存状态不一致、仅修改自动化选项不立即应用：失败恢复原列表／值，成功后标记变更。
- 核心停止异常时仍丢弃状态：确认退出后再释放对象／清理状态；失败保留以便重试。
- 实际核心启动继承 CLASH_* 环境：与导入校验统一清除，避免外部启动环境改变行为；同时增加关键路径链接与配置大小检查。
- 恢复工具仅按核心路径终止进程且先删状态：现在拒绝与运行中管理器竞争，核对保存的 PID、路径和启动时间，保留状态供管理器确认清理；提供只读 -CheckOnly。未对真实系统执行恢复写入。
- 新 YAML DLL 纳入构建／打包白名单、固定哈希验证和 MIT 声明；不放宽对任意二进制的发布限制。

## 验证与限制

隔离回归覆盖导入边界、组图校验、嵌套 select 故障切换、冷却、全部失败、直连排除、过期结果。真实 Mihomo 配合两个本机 HTTP 测试代理验证 fallback 主线故障→备用→主线恢复，入口及下级引用保持不变。既有核心启停、应用代理参数、运行中恢复、watchdog 身份及崩溃清理回归通过，测试前后 Windows 系统代理一致。

没有使用真实节点进行连通性／速度测试，没有补做商店／游戏共存、干净 Windows、高 DPI 或 Codex WebRTC 验证。没有增加透明接管驱动、安装器、自动更新或加密凭据库。保留旧档案，不自动重写私人配置。

PowerShell 7 与 Windows PowerShell 5.1 打包／单元验证通过；对应源码在中文路径可重编译，包内版本、文件清单与哈希匹配。本地 YAML 只读校验未改写来源文件和设置。旧档案需重新导入才能获得原组结构。测试进程命名已隔离，避免并行回归误识别另一次测试进程。

项目内仅删除确认重复的 `CodexProxyManager.atomic-old.exe`；哈希相同的 `CodexProxyManager.exe` 备份仍在，可恢复。另外删除本轮 7 个中间测试构建中的 14 个临时 EXE／DLL；它们可由源码重建，最终通过的回归构建保留。其余历史归档有回滚价值，未当作垃圾批量删除。所有本轮手动文件删除按普通文件及父路径确认、独立 Remove-Item（无 -Force）、独立 Test-Path 顺序执行，均确认不存在。保留测试模式留下的隔离目录，未递归删除目录。

发布安全回归通过：固定 DLL 哈希可接受，改名 DLL 与篡改 DLL 被拒绝；原有凭据模式、路径越界／链接、私人文件及 Git 枚举负例通过。73 份工作区候选文件有限扫描与 PowerShell 语法检查通过。这不是完整历史或未知编码秘密扫描。

## 后续优先级

1. 安装／升级体验：可信核心与规则库校验、带进度的组件准备、完整包与安装器、签名及失败回滚。
2. 策略编辑体验：入口组明确选择、导入预览／差异、远程 provider 的受控导入及更新事务；目前依赖外部 provider 的组明确拒绝。
3. 工程质量：进一步拆分 ManagerContext，统一可取消后台操作／状态机，补充原生窗口自动测试与多 DPI／干净系统矩阵。
4. 性能及隐私：对商店／游戏变慢做可复现测量，再优化轮询和网络行为；评估 Windows 凭据保护。不要把参数请求当作零泄漏保证。

# 全项目审查记录 · v0.11.2（历史）

日期：2026-10-14。作者：Rinko。以下是 v0.11.2 当时的本地审查快照；该版本未单独发布，修复现已纳入 v0.11.3 预览版。

## 审查范围

覆盖当前产品源码、隔离测试、构建/打包/迁移/发布安全脚本、工作流、说明文档、示例、许可证和维护工具。审查保留此前 v0.11.1 的未发布修改，不覆盖或清空个人配置。

当前工作区可维护文件共 57 份，包含 19 份产品 C# 源码和 9 份测试 C# 源码；其余为脚本、文档、模板、工作流和声明材料。

生成的 app 文件由源码重新构建并同步文档；runtime 是第三方二进制/数据库，只核对文件元数据、哈希及当前核心可运行性，不声称审计了它们的源码或来源。artifacts 是历史产物、设计和私人可恢复归档，仅核对分类/排除边界，不将历史备份当作当前源码，也不公开里面的私人配置。.git 内部认证、未引用对象和完整历史不属于本轮代码认证范围。自动工作区扫描只是有限模式检查。

本机核心的 Authenticode 检查为 NotSigned；计算 SHA-256 和成功执行不证明其来源可信。未替换该第三方核心，也未补做其供应链认证。

## 验证与边界

本地验证包括 C# 编译、PowerShell 7 完整隔离回归、Windows PowerShell 5.1 单元回归、发布安全/目录迁移/打包检查。完整回归使用本机临时上游和独立核心，检查 Windows Internet Settings 及原档案不变；不使用真实节点、不关闭正在使用的 Codex，不启用全局代理或 TUN。具体执行结果以 [验收记录](ACCEPTANCE.md) 为准。

Chrome 隔离本地 WebRTC 回归也通过，仍仅覆盖该次临时浏览器、本机 STUN 和代理 HTTP 场景；不把结果推广为现有会话或公网无泄漏。

没有完成独立 Windows、高 DPI、四类真实来源、真实 Codex 桌面恢复体验或商店/游戏共存性能验收。WebRTC 参数仍不是保护保证；浏览器隔离测试也不证明当前会话或公网无泄漏。普通启动应用的运行中接管、凭据加密、安装器、自动更新、代码签名和其他后端未实现。用户提供的自定义核心/配置需另行核对，不应因管理器测试通过就假定它们安全。

## 项目评价与下一阶段

这是一个定位明确、已有产品雏形的应用专用代理管理器。应用与用户数据分离、源码对应发布包、固定日志、脱敏诊断和隔离测试是优点；它不是代理协议实现，也不是系统级进程防火墙。

当前瓶颈是单一 ManagerContext 仍承担界面编排、会话、节点和自动化，多档案/多后端越多，状态竞争和验证成本越高；自定义配置检查、错误分类与真实客户端验收也需加强。原生桌面技术本身不是必须重写的理由。

导入保存失败时列表会回滚，但该次新建的私人 provider/config 文件可能保留；导入文件与列表尚未做成统一事务，不能把列表回滚理解为清除了所有失败产物。手工并发编辑配置及同用户攻击也不在当前防护范围。

建议先完成可靠性与共存实测，再把会话服务、控制客户端、节点策略和 UI 编排拆成稳定边界；之后才做新的后端或按进程接管。v1.0 应以支持范围和验收结果定义，而不是靠增加开关或改版本号达到。现阶段适合继续作为面向愿意反馈用户的预览版，不宜宣称全面兼容、零泄漏或稳定通用代理。

## 后续优化 · v0.11.3

已按上述方向拆出 ProxySessionService、NodeControlService、DashboardPoller 和独立 RecoveryWatchdog，并增加不可变 ControllerClient、可注入接口和 NodeHealthPolicy。主入口/UI 文件由本轮基线 1468 行缩至 991 行；这是职责转移和可测试性改善，不是用行数证明运行性能。会话集成直接测试服务，接口契约、分离控制通道和快照隔离可用模拟客户端独立验证。

尚未完成通用后端接口、多会话、事务式导入或真实共存性能定位。v0.11.3 继续以预览版发布，实际本地验收结果见 ACCEPTANCE.md。原 v0.11.2 审查范围与统计是当时快照，不代表重构后的文件数。维护者决定本次暂不执行真实共存测试，不将其视为已通过或变慢已修复。
