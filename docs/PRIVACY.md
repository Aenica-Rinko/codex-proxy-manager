# 隐私与数据边界

本说明描述当前实现，不是匿名性保证。作者署名为 Rinko。项目不是凭据保险箱，也不会隐藏你在 GitHub 上已经公开的账号信息。

## 隐私中心、日志与截图模式（v0.11.0）

v0.11.4 本地文件导入读取用户主动选择的 YAML/YML/TXT，复制内容到用户目录的 provider 文件，生成管理器专用配置；不修改或持续读取原文件、不保存原始来源路径、不自动上传。provider 副本可能包含文件原有的节点、订阅和其他敏感文本，仍是未加密私人数据。校验用独立核心，只提供随机密钥保护的回环控制接口，不启动目标应用，不复制源配置的 TUN/DNS/全局端口与规则，不主动测速或刷新远程 provider。临时校验文件会尝试在核心退出后删除；持续锁定等故障可能留在私人目录。只导入可信文件，校验不证明第三方核心或节点安全。

主界面左侧“隐私保护”可在代理运行时查看网络选项状态：未启用、已配置待下次启动、已请求但行为未验证、不支持当前启动模式。编辑应用选项仍需先停止会话并退出目标应用。

新日志默认只保存固定事件及错误类别。节点名称、地址、订阅、凭据和原始异常不会进入新日志；未分类的核心输出不保存。核心启动后尝试通过本项目的本机控制接口将日志级别设为 warning，失败也不会绕过日志过滤。日志写入及启动检查时执行大小/时间轮转：每份新日志约 1 MB，最多一份轮转备份，保留期限为 7 天；这是按启动或写入触发的清理，不是程序关闭后仍工作的后台任务。

**旧版本日志没有被追溯脱敏。** 历史文件和备份可能含私人信息或超过新大小上限。停止会话后，可在隐私中心主动确认“清理本项目日志”，只删除 `manager.log`、`mihomo.stdout.log`、`mihomo.stderr.log` 及各自 `.1` 备份，不递归清理目录，不删除节点、设置或其他文件。删除后程序内无法恢复；活动会话期间禁用清理，目录或文件含链接时拒绝清理。

“截图隐私模式”将本项目主界面的节点名称改成编号，隐藏应用名称、档案名称、入口地址、搜索内容和节点工具提示。切换、收藏仍使用原始身份，关闭后恢复正常显示，不更改配置或路由。为避免弹出私人内容，模式开启时限制应用/档案管理、帮助文件检查和日志目录入口，并隐藏通知及错误弹窗详情。诊断报告仍可查看。它不隐藏其他软件、已经打开的资源管理器、Windows 用户身份、进程内存或磁盘数据，不提供操作系统级截屏阻止。

v0.11.2 将限制同时落实到托盘入口和配置处理函数。控制请求统一拒绝重定向、限制响应大小并设置总截止时间；不接受 URL 内嵌用户名、查询或路径。状态保存为原子替换，并记录私人会话/进程身份用于谨慎恢复，不进入脱敏报告。设置和收藏文件拒绝链接路径；这些措施不等于凭据加密或同用户攻击防护。

## 隔离本地 WebRTC 行为测试

隐私中心的“运行本地 WebRTC 测试”只对选中的兼容 Chrome / Edge EXE 开放，且需要启用 WebRTC 限制。不会自动运行，也不会注入或远程调试当前正在使用的 Codex/浏览器。

测试创建独立临时浏览器目录、回环 HTTP 代理、回环 STUN 接收器和仅本机的临时调试端口，分别测量未启用限制的基线和当前限制选项。测试网页只使用虚构域名并由本地测试代理响应，不连接公网 STUN 或泄漏检测网站，不记录 IP/ICE 候选地址，也不读取已有浏览器档案。测试结束或取消后关闭本次创建的浏览器并尝试删除其唯一临时目录；文件被占用时可能保留该测试目录。

只有基线确实收到 STUN 包、限制场景未观察到 STUN UDP/host 候选且代理 HTTP 请求成功，才显示“隔离本地测试通过”。没有有效基线、运行异常、超时或取消均不会认定通过。测试结果只覆盖该 EXE 本次隔离场景，不证明现有会话、公网 DNS、IPv6 或所有应用路径无泄漏。Codex/Electron 当前没有通用的自动行为测试入口，仍标为未验证。

## 应用网络隐私选项（v0.10.4 起）

在“管理应用”中为每个应用保存以下选项。保存后必须完全退出目标应用，再手动点击“启动应用”；打开管理器不会启动它们。旧设置没有这些字段时，WebRTC 限制默认请求开启，DNS 和 QUIC 选项默认关闭；读取旧设置不会自动改写文件。

| 选项 | 请求的行为 | 兼容性与影响 |
| --- | --- | --- |
| 请求限制 WebRTC 非代理 UDP | 向兼容 Chromium 浏览器请求 `disable_non_proxied_udp` 策略，限制绕过代理的 WebRTC UDP | 可能影响语音、视频及点对点连接；不等于关闭整个 WebRTC API |
| 限制浏览器本机 DNS 解析 | 阻止 Chromium 主机解析器解析非回环域名，HTTP 代理请求仍将域名交给本地代理 | 内网域名和需要直接解析的功能可能失败；不是把所有 DNS 都强制送进节点 |
| 关闭 QUIC / HTTP3 | 请求 Chromium 禁用 QUIC，让支持回退的 HTTP 请求使用 TCP | 可能影响性能；不禁止应用所有 UDP，也不改变节点使用的传输协议 |

这些设置只作为目标进程的启动参数提供，不修改 Windows DNS、系统代理、注册表策略、全局环境变量、浏览器配置文件或防火墙。环境变量模式禁用这些选项，保留已有偏好以便切回兼容模式，但启动时不会发送浏览器参数。

**兼容性不能由“Chromium / Electron 模式”名称保证。** Chrome 的普通浏览器参数与部分旧版/无头参数不同，所以启动器提供两种 WebRTC 参数。Electron 应用通常需要由应用内部调用 `webContents.setWebRTCIPHandlingPolicy`；外部参数可能被忽略。Codex、Firefox、自定义内核和辅助进程的实际行为不能据此认定已受保护。界面与诊断显示“请求限制、效果待验证”，不会把配置开关当作实测结果。

本机 Chrome 的无头隔离测试使用随机本地端口和临时浏览器目录：只向回环 STUN 测试入口发包，未启用限制时观察到 UDP 和 host 候选，启用后未观察到它们，代理 HTTP 请求仍可完成。没有使用公网 STUN 或泄漏检测网站，没有记录候选地址。它验证的是该浏览器、本地测试场景，不是 Codex/所有版本的认证，也不排除其他网络路径。

浏览器 DNS 限制不覆盖 Mihomo 的节点域名解析、直连规则、订阅服务、Node.js/原生辅助进程或应用自行实现的解析器。保留的回环例外用于本机服务。HTTP 代理入口和这些选项都不是防火墙级的断网保护：代理停止后，忽略代理或隐私参数的程序仍可能自行直连；DIRECT 规则也会暴露本机公网出口。IPv6、浏览器指纹、账号身份及节点运营者可见信息没有被统一隐藏。

参考：[Chromium WebRTC 策略](https://chromium.googlesource.com/chromium/src/+/376fc41e87a058f7a7b300b0ec3a4982b4ec0960/components/policy/resources/templates/policy_definitions/Miscellaneous/WebRtcIPHandling.yaml)、[Chrome 命令行偏好映射](https://raw.githubusercontent.com/chromium/chromium/main/chrome/browser/prefs/chrome_command_line_pref_store.cc)、[Electron 命令行支持范围](https://www.electronjs.org/docs/latest/api/command-line-switches)、[Electron WebRTC API](https://www.electronjs.org/docs/latest/api/web-contents#contentssetwebrtciphandlingpolicypolicy)。

## 本地保存了什么？

真实数据位于 `%LOCALAPPDATA%\CodexProxyManager`，包括设置、应用路径、节点档案、订阅地址、控制密钥、收藏、核心缓存、日志和运行状态。配置文件可能以明文包含凭据；不要假定只有本程序能读取它们，也不要将其放入公开或共享的同步目录。

本项目不应收集或发布你的真实订阅、节点服务器地址、密码、UUID、控制密钥、个人文件路径或私人邮箱。源码中的示例仅使用回环地址、示例域名和模拟数据；发布所需的署名与账号归属不等于匿名发布。

## 哪些操作会联网？

- 启动目标应用后，应用会访问自身服务，按配置直连或经过你指定的节点/上游。
- 订阅导入后的拉取、自动更新与手动刷新会联系你提供的订阅服务。
- 核心健康检查、节点延迟测试、自动选优或故障切换可能产生外网探测。
- 默认连接诊断只检查本机；勾选外网延迟测试后，会通过当前节点访问诊断所注明的探测目标。
- 外部 API 模式访问你配置的本机控制接口；切换共享策略组可能影响其他使用者。

订阅服务、代理服务和目标网站各自可能看到相应连接信息。代理不等于匿名；本项目没有承诺对这些第三方的数据处理负责。不要使用不信任的节点、订阅或替换核心。

## 反馈前如何检查？

优先在“连接诊断”中导出脱敏报告，并自行打开检查后再分享。程序不会自动提交报告。原始日志不是脱敏报告；即使仓库为私有，也不要把日志、设置或截图中的秘密提交进去。

截图要遮住节点名称、地址、订阅、用户名、磁盘路径及其他应用内容。反馈时提供问题步骤和可公开的版本信息即可，不需要真实账号或真实节点。不要把密钥作为 Issue 标题、文件名、分支名或提交信息。

## 上传与发布约束

- 只提交明确审核过的源码、文档和无凭据模板，不使用整个项目目录拖拽上传。
- 不提交 runtime、用户数据、EXE、ZIP、快捷方式、日志或历史私人备份；.gitignore 不能删除已经跟踪的秘密。
- v1.1.0 唯一批准的第三方二进制源码依赖是固定哈希的 YamlDotNet.dll，随 MIT 许可证公开；这不允许加入其他运行内核或私人文件。策略组健康检查会访问档案指定的测试地址，原策略组的直连成员仍可能被用户手动选择，不能视为系统级防泄漏保护。
- 提交作者采用 Rinko；上传前检查作者和提交者元数据，使用 GitHub 的 noreply 地址而不是私人邮箱。
- 私有仓库也不是上传秘密的理由。自动扫描只能发现有限模式，还需复核实际上传文件和提交元数据。
- 如秘密已经提交或分享，先撤销/轮换该秘密，再处理文件与历史；仅删除当前文件不能撤回已下载副本。

当前发布扫描的范围和局限见 [开发说明](DEVELOPMENT.md)。涉及账号授权、协作者或公开仓库的变更需要单独确认，不能因“继续开发”自动扩大访问权限。
