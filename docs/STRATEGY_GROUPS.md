# 策略组与自动故障切换（v1.1.0）

这是本地候选版本新增功能，公开 v1.0.0 不包含。升级不重写旧档案；请停止代理后重新导入原 YAML，并启用新档案。原文件不修改，重新导入会创建新副本。

## 导入后保留什么

- 保留内联 `proxies` 节点及其参数，原 `proxy-groups` 的名称、顺序、成员、组间引用和支持的健康检查／筛选参数。
- 支持 select、fallback、url-test、load-balance，以及 include-all-proxies；没有外部 provider 的 include-all 转换为 include-all-proxies。
- 支持 YAML 流式／块式写法和有界的锚点／合并键。拒绝重复键、重复节点／组名称、缺失引用、循环组或拨号链、显式类型标签、多文档及超限嵌套。上限：10 MiB、5000 节点、256 原策略组、48 层嵌套。
- 不继承系统代理、TUN、DNS、全局 rules、端口或控制接口，不下载 provider。组依赖远程／外部文件 provider 时明确拒绝；请先在原客户端展开节点。relay 和不支持的组字段明确报错。不是任意客户端配置的无损转换器。

另外添加一个管理器入口 select 组，默认名 Codex Proxy，遇到同名则增加 `(CPM)` 后缀，原名称不改。入口包含原组及所有内联节点，初始选择原文件的第一个组；没有组则选择首节点。原文件的 rules 不用于猜测默认出口，导入后请确认入口选择符合预期。

导入结果分别显示原节点数与原策略组数。例如 7 节点、3 原策略组不是 10 个真实节点；管理器另加的入口组不算原组。主列表是入口成员，包含节点和组。保存快照仅在本机用户目录。

## 怎么操作

1. 代理档案 → 本地文件导入 → 选择文件 → 添加并设为当前。
2. 手动启动代理。主列表选择希望使用的节点或原策略组。
3. 左侧“策略组与引用”打开组列表。下拉选择组，双击成员中的组名可进入下级组。
4. select 组可以选择成员并点击“将选中成员设为此组出口”；修改下级组不会改变入口组。自动组只展示，决定交给核心。窗口关闭后主面板继续刷新。截图隐私模式下不开放此入口。

旧版本已导入的节点仍可用，但不会自动出现源文件中的组。URL 订阅和分享链接模式仍使用节点 provider；要保留完整组结构，请把可信 YAML 保存到本地再导入。

## 两层故障切换

`fallback` 按原成员顺序选择可用线路，`url-test` 按原策略选优，`load-balance` 按原配置分配连接，均由 Mihomo 处理。保留显式 interval、timeout、lazy、url；自动组未提供时补充 300 秒、5000 毫秒及 gstatic 健康检查地址。显式 interval: 0 仍保留，意味着不启用定时检测。配置不等于实际线路可达。

管理器的“节点连续失败时自动切换”只补充 select 组：约每 30 秒沿当前引用链找到最后一级选择组，连续三次探测失败才测试该组的备用成员。仅切换到返回有效延迟且引用图不含直连／拒绝出口的候选，尝试后冷却 120 秒；全部失败则保留原选择，不改成 DIRECT。手动切换、档案变化或停止代理会让过期探测失效。首次选优也不会覆盖入口已选择的策略组。

经过 fallback／url-test／load-balance 时，管理器退出自己的故障切换流程，避免相互竞争。关闭管理器的故障切换选项不会关闭原自动组的健康检查。核心自动切换主要影响新连接，已有会话可能需要重连；不是系统级断网保护。
